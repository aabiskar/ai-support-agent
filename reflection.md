# Project Reflection: Customer Support AI Agent

Building this customer support AI agent helped me understand how a single AI agent can use multiple tools and AWS services to handle e-commerce requests. Rather than relying only on a language model, the agent can retrieve knowledge, call external services, perform calculations, and interact with web pages through dedicated integrations.

One important integration was Amazon Bedrock AgentCore Gateway with MCP tools. I integrated an API-based order-tracking target and a Lambda-based refund-processing target. During testing, I verified that the agent retrieved the correct order total of $139.99 for ORD-002 and passed that amount to the refund tool. This demonstrated why an agent must retrieve and validate business data before initiating a financial action.

I implemented retrieval-augmented generation (RAG) using the Amazon Bedrock Agent Runtime Retrieve API. CloudWatch logs confirmed that the deployed agent invoked `search_knowledge_base` when asked about Platinum loyalty benefits, demonstrating how retrieved knowledge can ground responses in relevant information.

Browser execution presented a deployment challenge involving Playwright's Node.js binary permissions. I investigated the runtime error, identified the Node binary execution issue, and worked around it by copying the binary to `/tmp/node` and setting `PLAYWRIGHT_NODEJS_PATH`. The browser then retrieved a live web page successfully. This taught me that dependencies can behave differently in a managed runtime than in a local development environment.

I implemented loyalty calculations for standard, device, and fresh product categories, with points earned from the final order total. The standard and fresh-category tests returned the expected values, including 99 points earned and 349 remaining for the standard Gold-member test. I also simulated a Code Interpreter failure locally and verified that the fallback applies the Gold tier discount, returns a $135 final total on a $150 order, preserves the existing points balance, and clearly reports that points calculations are unavailable. This verifies the fallback logic, although it does not establish that the Code Interpreter service itself is fixed.

Persistent memory was another important learning area. After updating namespace handling and testing separate sessions with the same customer ID, the agent successfully recalled the customer's name and response preference.

For production, security is a key consideration. If the Gateway uses the `NONE` authorizer, anyone able to access its endpoint may be able to invoke refund operations. I would configure an appropriate Cognito JWT authorizer and add monitoring and integration tests to detect authorization failures, tool errors, and repeated loyalty fallback usage.
